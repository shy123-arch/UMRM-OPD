# vt_head_opd_v860 第一版结果（2026-10-15）

**范围**：v860 冻结划分；所有结论只来自 **VAL（96 条 / 25 个来源）**，TEST（182 条）封存、从未加载。门和选模规则在出任何 VAL 生成结果之前写进了 README。p 值未做多重比较校正；每项只训练了一次（单随机种子）。
**完整表**：`runs/summary_val.md`（由 `summarize.py` 生成）。配对比较：`compare.py`，按来源 cluster bootstrap 95% CI + Wilcoxon。

## 0. 一页结论

1. **4B 够用（G-A 通过）。** Qwen3-VL-4B SFT → Kimodo-TPH 与路线 6 的 7B SFT 持平，R@10 0.267 vs 0.253，差 +0.014，CI [−0.031, +0.067]。单卡显存峰值 9.8 GiB，SFT 每个 epoch 约 16 分钟。
2. **自有动作头（HumanML3D 预训练）可用，且在同一文本下不逊于 Kimodo（G-B、G-C 通过）。**
   - HumanML3D test 1024 条：生成动作的 TMR R@3 为 0.855，与同一 VQ 重建的真值（0.860）几乎相同（比值 0.99）。
   - gt3p oracle 文本 + 真值时长：自有头（PICO 微调）R@10 0.559 vs Kimodo 0.458，差 +0.101，CI [−0.057, +0.230]；t2m 相似度 +0.060，CI [+0.002, +0.116]。
   - **注意评价器同源**：原版 TMR 和自有头都基于 HumanML3D，自有头有域内优势；只做 HumanML3D 预训练的头在 TMR 上最高（0.628），但几何指标更差。
3. **整条链"视频 → 4B → 文本 → 自有头"在 VAL 上是目前最好的可部署结果之一。**
   - SFT → 自有头（仅预训练）R@10 0.306；SFT → 自有头（完整事件 E1）0.316。
   - 显著优于视频端到端的 HERO-FT（0.191）：+0.115，CI [+0.018, +0.212]。
   - 与 Kimodo-TPH（0.267）的差异不显著。
4. **特权教师的上限很低，这是本版最重要的发现。** 教师在 VAL 上看到真实动作信息 z 后，计划准确率达到 0.99，但语义 R@10 只从 0.267 升到 0.351（Kimodo-TPH），从 0.253 升到 0.372（自有头）。z 主要改善"怎么动"（终点误差 1.15 → 0.54 m），对"做什么反应"帮助有限。OPD 能从教师学到的东西被这个上限卡住。
5. **OPD（反向 KL）出现了预测中的"向众数塌缩"。** 第 1 个 epoch（探索性读数）：
   - 计划准确率 +0.044，CI [+0.007, +0.084]；Kimodo-TPH 静止率 −5.6 个百分点（显著）；语义持平。
   - 方向分布 TV 从 0.22 升到 0.43：预测 forward 72 条（真值 32 条），run 从 10 条降到 2 条，用词种类从 278 降到 251。
   - SFT 学生的计划准确率本来就只比"永远猜训练集多数类"（0.542）略高。准确率的上升主要来自更多地猜众数，而不是更会读视频。这正是 ROUTE.md §3.3 陷阱 1 说的"反向 KL 在 z 不可推断时趋向几何平均"。
   - 预登记的 epoch 2：**G4 不通过**。语义 R@10 +0.003，CI [−0.034, +0.037]；计划准确率 +0.048，CI [+0.022, +0.074]；方向 TV 0.22 → 0.40。语义没有像 DPO 那样被拉低。详见 §3。
6. **VPP2 式"完整事件"（E1）：** 用未截断目标微调动作头后，在 SFT 预测文本上 R@10 +0.062，CI [+0.008, +0.122]，Wilcoxon p = 0.10；oracle 文本上无差异。方向为正但证据偏弱，属于探索性结果。

## 3. G4-OPD（预登记：epoch 2）

**判定：不通过。** 语义没有提升，方向分布的偏移超过了容忍线。

| OPD e2 vs SFT（主臂 Kimodo-TPH） | 差值 | 95% CI | p |
|---|---|---|---|
| R@10 | +0.003 | [−0.034, +0.037] | 0.98 |
| t2m 相似度 | −0.004 | [−0.019, +0.011] | 0.57 |
| 同类 R@3 | −0.028 | [−0.075, +0.020] | 0.31 |
| 计划准确率 | **+0.048** | **[+0.022, +0.074]** | 0.012 |
| 静止率 | **−0.035** | **[−0.064, −0.007]** | 0.12 |
| 方向分布 TV | 0.22 → **0.40**（恶化 0.18 > 0.1） | | |
| 时长分布 TV | 0.46 → 0.38（改善） | | |

- **第二读数**（三个自有头）：R@10 差值分别为 −0.003、+0.007、−0.038，CI 都跨 0。结论相同。
- **与路线 6 的 DPO 对照**：两者都没有提升语义，但 OPD 没有像 DPO 那样把语义拉低。DPO 相对其 SFT 的 t2m 为 −0.028，CI [−0.053, −0.005]；OPD 为 −0.004，CI [−0.019, +0.011]。OPD（4B）在 R@10 上高于路线 6 的 DPO（7B）+0.069，CI [+0.003, +0.131]，但两者基座不同，这只是参考。
- **训练成本**：OPD 不需要生成器。DPO 用了 13,956 次 Kimodo 生成，OPD 为 0 次。
- **原因分析**：
  1. 特权教师的语义上限本身就低：在 VAL 上用了真值信息，R@10 也只高 0.083，CI [−0.000, +0.161]。z 只包含运动学信息，不包含"做什么"。
  2. 反向 KL 把教师条件分布按 z 做几何平均，学生在 z 推不出来的字段上向众数塌缩：预测方向 forward 70/96，真值 32/96。计划准确率的提升主要来自猜对多数类。
- **第 2 版建议**（每条都对应上面的证据）：
  1. 把 `<plan>` span 排除在 KL 之外，或只对 `<reaction>/<exec>` 计算 KL；
  2. 混入前向 KL，或用 GKD 的广义 JSD（β 约 0.5），抑制众数塌缩；
  3. 让特权信息带上"做什么"的语义：正式 636 条有 mental_reasoning，或者用反应发生后的画面（需先确认源视频在盘上）；
  4. 等 1.5k 数据到位后重跑。

**本版可以写的结论**：同尺寸、仅运动学特权信息的 on-policy 自蒸馏，能稳定提升计划字段的准确率、降低静止率，并且不像 DPO 那样损害语义；但在独立语义指标上没有超过 SFT。

## 4. 其他发现

- **动作头在 PICO 上微调很快过拟合**：VAL CE 在第 250 步最低（8.52），之后一路上升到 12，而训练 CE 持续下降。582 条对 HERO 规模的 transformer 太少。微调提升了几何（oracle MPJPE 0.714 → 0.648），但降低了 TMR 语义（R@10 0.628 → 0.559，t2m −0.038，CI [−0.072, −0.002]）。考虑到评价器同源，"仅预训练"与"微调"孰优，需要非 TMR 的评价（例如人评）来定。
- **v860 动作目标有截断**：train 19.9% 的反应在 4.4 s 处被截断，其中 61% 的尾段仍有实质动作（`runs/diag_truncation.json`）。E1 的完整事件目标与原 88 帧特征在未截断条目上一致（最大差 5.7e-6）。
- **学生的时长预测几乎塌成单值**：SFT 时有 77/96 预测为 2.5 s，时长准确率只有 0.31（路线 6 的 7B 为 TV 0.25）。时长不能靠视频预测，这和 route6 G2b 的结论一致。

## 5. 工程记录

- Qwen3-VL 与 transformers 5.3 不兼容：`get_rope_index` 遇到带时间戳的视频会 StopIteration，已通过把 grid 展开为 T×[1,h,w] 修复（视觉特征差 0）。
- OPD 的采样器：用合并后的权重副本，每个优化步刷新一次；与 `merge_and_unload` 的 greedy 输出逐字一致。HF 逐步解码约 90 ms/步，与 batch 基本无关，所以一次生成 4 个视频 × K=4 个样本。左填充批量计算 log-prob 时会因注意力 kernel 产生个别 token 差异（最大 0.13），所以教师和学生的 logits 都按单视频计算。
- 一个 epoch 的 OPD（582 条 × K=4）约 85 分钟，显存峰值 33 GiB；整个过程**不调用 Kimodo**。
- 一个踩坑：`pkill -f` 的模式串匹配到了执行它的 shell 自身，导致命令中途中断；已改为按 PID 处理。

## 6. 局限

- VAL 只有 96 条 / 25 个来源；原版 TMR 对左右、先后不敏感；每条视频只有一条真人动作；没有人评。
- 自有头与评价器同源（都基于 HumanML3D），自有头在 TMR 指标上可能偏高。
- HumanML22 口径：手部关节按前臂比例补全，只影响 MPJPE 类指标。
- OPD 只跑了一组超参（K=4，lr 5e-5，2 epoch，T=1 采样）。
