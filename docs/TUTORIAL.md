## 0. 一句话任务

给模型看一段第一人称视频，视频恰好停在"我"做出反应之前（比如在鬼屋里，同伴刚喊了一声"又来了！"）。模型要预测"我"接下来 1–4 秒怎样反应，并生成一段三维人体动作（22 个关节，20 帧/秒）。

难点分两层：

1. **决策**：该做什么，是转身跑、蹲下，还是伸手去接？这需要理解视频里的情境，而且合理的答案往往不止一个。
2. **执行**：把决策变成物理上合理的全身动作，包括走多远、往哪转、持续多久。

整条路线的核心思路是**用文字把这两层隔开**：视觉语言模型（VLM）负责"看懂并做决定"，把决定写成文字；动作头负责"把文字变成动作"。这样两边可以各用最合适的数据分别训练。

> **为什么不直接从视频端到端生成动作？** 我们的配对数据只有约 1.2k 条，而"文字–动作"数据集 HumanML3D 有约 3 万段动作和 7 万条描述【本地】。端到端模型只能用那 1.2k 条学；分成两段之后，动作那一段可以先在 HumanML3D 上学会"听懂指令做动作"。实测也支持这一点：视频端到端的 HERO-FT 是 R@10 0.191，"VLM 写文字 → 动作头"是 0.306，差异显著（v860）。

## 1. 你的原设想，逐句拆开

原话："借 Qwen-VL 一个 4B 模型，SFT 然后接动作头（可能需要找个 HumanML3D 或者 ego 数据集重定向，然后预训练，分段弄出视觉到文本、文本到动作的能力），然后最后一层的那个输出语义信息，然后 LoRA 可以选也可以不选。再 OPD 自蒸馏到一个 student 模型（同 Qwen-VL 4B），反向 KL 去做。"

| # | 原话 | 含义 | 当前实现 | 实测结论 |
|---|---|---|---|---|
| ① | 借 Qwen-VL 一个 4B 模型 | 用开源 VLM 当"眼睛和大脑" | Qwen3-VL-4B-Instruct | 与 7B 持平（R@10 +0.014，CI [−0.031, +0.067]），所以选 4B |
| ② | SFT | 用标注教它写反应 | LoRA SFT，输出三行：`<reaction>` / `<exec>` / `<plan>` | 格式稳定；"决定做什么"仍是最大瓶颈 |
| ③ | 接动作头 | 文字 → 动作的生成器 | 自有动作头：RVQ 动作分词器 + 掩码 Transformer + 残差 Transformer（MoMask / HERO 一系） | 显著优于视频端到端的 HERO-FT（0.306 vs 0.191） |
| ④ | 找 HumanML3D 或 ego 数据集重定向，然后预训练 | 自己的动作数据太少，先借大数据集 | 反过来，把我们的 PICO 动捕**转成** HumanML3D 格式；动作头先在 HumanML3D 上预训练 6 万步，再在 PICO 上微调。ego 数据集没有用（理由见 §4.6） | 预训练后自检 R@3 0.855（真实动作 0.860）；在 PICO 上微调 200–300 步就开始过拟合 |
| ⑤ | 分段弄出视觉到文本、文本到动作的能力 | 两段分开训练 | V→T（VLM SFT）和 T→M（动作头）完全分开训练，推理时用文字串起来 | 可行；出错时能分清是哪一段的问题 |
| ⑥ | 最后一层的那个输出语义信息 | 用 VLM 最后一层的隐状态作动作头的条件 | 做了 4 种：A4、**A36**、S36、V36（§4.10） | **A36（冻结原版 4B 重新读 exec 文字，只取最后一层）最好：0.291**。和原话最贴近的 V36（学生自己的最后一层，带视频语境）是 0.253，没有额外增益 |
| ⑦ | LoRA 可选可不选 | 要不要微调 VLM | 写文字的 VLM 必须加 LoRA（不加时零样本格式合格率只有 49%）；但给动作头提供条件时，**关掉 LoRA 反而更好**（A36 > S36） | "可选"最后落在了接口这一侧 |
| ⑧ | OPD 自蒸馏到同为 4B 的学生，用反向 KL | 学生自己采样，再逐 token 向教师靠拢 | 共 9 版：v1–v5 的教师带特权信息 z；v6 不带 z，换成 8B 教师 | 没有一版显著优于 SFT。z 推不出来时，纯反向 KL 会塌缩；v6 不塌缩，但教师本身只比学生强一点 |

## 3. 跟着一条样本把整个流程走一遍

样本 `MCQ199_0001`（VAL 组，类别 E）。

### 3.1 原始素材（详见 `docs/DATA.md`）

| 字段 | 内容 | 谁能看到 |
|---|---|---|
| 视频 `clips/MCQ199_0001.mp4` | 鬼屋里，同伴喊 "It's coming again!"；视频在"我"反应前截断 | 学生、教师（输入） |
| PICO 动捕 `pico/MCQ199_0001.npz` | 24 个关节，约 80 帧/秒，是这次反应的真实动作 | 只用作答案 |
| `reaction`（人工，第一人称） | I intend to grab my companion and retreat quickly. | 答案 |
| `exec`（gt3p，第三人称动作描述） | A person immediately turns around, uses one hand to grab the arm of the companion beside them, and runs forward while pulling the companion with them. | 答案 |
| `plan_raw`（从动捕自动测量） | 时长 3.05 s；位移 3.28 m（向前 −0.17 m、向右 +3.27 m）；朝向转了 −65°（向右） | 只有 v1–v4 的教师看得到 |
| `plan`（离散化） | locomotion=run; direction=right; turn=right; posture=upright; duration=3.5 | 答案 |
| `mental_reasoning`（人工"内心想法"） | I hear one companion shout, "It's coming again!" ... If we stay there, we may be caught, so I need to take my companion away immediately and look for cover. | 只有 v2–v5 的教师看得到 |

**plan 怎么从动捕算出来**（`third_party/umrm_eval/harness_v1/plan.py`）【本地】：

- **locomotion**：
  - 位移 < 0.3 m 且路程 < 0.6 m → stay；
  - 位移 < 1.0 m → step；
  - 否则看 95 分位速度：< 2.2 m/s 为 walk，以上为 run。
- **direction**：位移向量落在 8 个 45° 扇区中的哪一个；位移 < 0.3 m 时为 none。
- **turn**：|转角| < 30° 为 none，> 135° 为 around，其余按正负分 left / right。
- **posture**：骨盆下降 > 0.25 m 为 crouch，上升 > 0.15 m 为 jump，其余为 upright。
- **duration**：取 1.5 / 2.5 / 3.5 / 4.4 秒中最接近的一档。

所以这条样本 3.05 s → 3.5 档，位移几乎全在右侧 → right，−65° → right。

### 3.2 训练目标：三行文字

```
<reaction> I intend to grab my companion and retreat quickly.
<exec> A person immediately turns around, uses one hand to grab the arm of the companion beside them, and runs forward while pulling the companion with them.
<plan> locomotion=run; direction=right; turn=right; posture=upright; duration=3.5
```

**为什么是三行**：每一行管一层，出了错能定位到是哪一层的问题。
- `reaction` 检查"决定对不对"；
- `exec` 把决定翻译成文本→动作模型听得懂的"A person ..."风格指令（HumanML3D 的描述就是这种写法）；
- `plan` 补上文字很难说清的数量：往哪走、转不转、持续多久。

这和让模型先写中间步骤再给答案（Chain-of-Thought）是同一类思路：把一个难的映射拆成几个可检查的小步骤。

学生看到的提示词（`pipeline/common.py` 中的 `PROMPT`）大意是："这段第一人称视频停在我反应之前，预测我接下来 1–4 秒做什么，严格输出三行"，并列出 plan 每个字段的可选值。

### 3.3 视频 → token（`prep_video_cache.py`、`vt_io.py`）

1. **均匀抽 16 帧**（不足 16 帧的短片取最大偶数帧），每帧缩放到不超过 360×640 像素。
2. **切块**：每帧切成 16×16 像素的小块，每 2 帧在时间上合成一组，16 帧 → 8 组。
3. **视觉编码器**（24 层 ViT，宽 1024）为每个小块算特征。
4. **合并**：相邻 2×2 个小块合成一个 token，投影到 2560 维，与语言模型同宽。每个 token 覆盖 32×32 像素 × 2 帧。
5. 一段视频平均约 **1,670 个视频 token**。这条样本是 8 组 × 220 = 1,760 个：每帧被缩放成 352×640，切成 22×40 个小块，2×2 合并后剩 11×20 = 220 个。每组 token 前面会插入一个时间戳，形如 `<0.1 seconds>`、`<0.5 seconds>`、……、`<2.7 seconds>`，让模型知道帧的先后顺序。
6. 每段视频只预处理一次并缓存。镜像样本在这一步做水平翻转。

此外，视觉编码器第 5、11、17 层的特征还会直接加进语言模型的前几层（DeepStack），让语言模型同时拿到浅层细节和深层语义。

> 工程坑【本地】：transformers 5.3 的 Qwen3-VL 遇到带时间戳的视频时，计算位置编码会抛 StopIteration。修法是把 `video_grid_thw` 从 [T, h, w] 展开成 T 行 [1, h, w]（`vt_io.per_frame_grid`），修复后视觉特征差为 0。

### 3.4 VLM 读视频、写三行（`sft.py`）

输入序列的排列：

```
[对话开头 + 1,670 个视频 token] [提示词] <|im_end|> <|im_start|>assistant  [三行答案] <|im_end|>
 └───────────────── 只读，不算损失 ─────────────────────────────┘ └──── 在这里算损失 ────┘
```

**训练（teacher forcing）**：
- 把正确答案整句喂进去，在每个位置让模型预测"下一个 token"。
- 损失是正确 token 的负对数概率（NLL / 交叉熵），只在答案部分计算。
- 设置：学习率 1e-4，最多 3 个 epoch，每 8 条累积一次梯度。
- 每个 epoch 结束后，在 VAL 上算每个 token 的平均 NLL，取最低的那个 epoch。
- 结果：4B 学生选 epoch1，VAL NLL 0.700；epoch2 升到 0.790，已经开始过拟合。

**推理（greedy）**：每一步取概率最高的 token。这条样本，SFT 学生写的是：

```
<reaction> I decide to run out of the door.
<exec> A person runs out of the door.
<plan> locomotion=run; direction=forward; turn=none; posture=upright; duration=2.5
```

"跑"对了，但方向（向前 vs 真值向右）、转身（不转 vs 向右转）和时长（2.5 vs 3.5）都不对，也漏掉了"拉同伴"。**这正是本任务的主瓶颈：从反应前的画面推断具体怎么反应。**

### 3.5 plan 决定动作有多长

duration = 2.5 s → 50 帧（20 帧/秒）→ 向下取整到 4 的倍数 = 48 帧 → **12 个动作 token**（每个 token 对应 4 帧）。
其他档位：1.5 / 2.5 / 3.5 / 4.4 s 对应 30 / 50 / 70 / 88 帧。

### 3.6 exec 文字 → 条件向量（接口 A36；`textenc.py`、`head.QwenAdapter`）

1. 拼成 `"<exec>" + " " + "A person runs out of the door."`，交给**冻结的原版 Qwen3-VL-4B**：不挂 LoRA、不给视频，只跑语言模型部分。
2. 取第 36 层（最后一层，已过最终 RMSNorm）上 caption 部分每个词的隐状态，得到 `[L, 2560]`（L ≤ 48）。
3. 适配器：
   - LayerNorm；
   - MLP（2560 → 512 → 512）；
   - 16 个可学习的"查询槽"对这 L 个向量做注意力池化，得到 16 个记忆向量；
   - 再对所有词取平均，得到 1 个全局向量。
4. 输出：全局向量 `[512]` + 记忆向量 `[16, 512]`，这就是动作头的条件。

**为什么用"另一个冻结模型"重新读文字，而不是直接拿学生自己的隐状态？** 见 §4.10。简单说：动作头在 HumanML3D 上预训练时，条件就是"冻结原版读文字"产生的。推理时保持完全相同的读法，分布才对得上；而且 OPD 改动学生时，动作头看到的输入分布也不会跟着漂移。

### 3.7 动作头生成动作（`head.py`）

1. **掩码 Transformer**：12 个第 1 层动作 token 一开始全部是 [MASK]。每一步预测所有被遮住的位置，保留最有把握的一批，其余重新遮住再猜，共 18 步。每一步都用 CFG（强度 4）放大条件的作用。
2. **残差 Transformer**：在第 1 层的基础上，依次预测第 2–6 层 token，补齐细节（CFG 强度 5）。
3. **RVQ 解码器**：6 层 token → 48 帧 × 263 维 HumanML3D 特征。
4. 反归一化，再恢复成关节坐标，得到 48 帧 × 22 关节 × 3 维，坐标系与 PICO 真值一致，可以直接送进评测器。

### 3.8 评测（`eval_head.py`、`compare.py`）

- **TMR**（在 HumanML3D 上训练的动作–文本对比模型）把生成的动作和 VAL 中全部 125 条标准 exec 描述映射到同一空间。如果这条动作与自己那条描述的相似度排进前 10，就算命中。
- 每条样本生成 3 次；R@10 是命中率（随机 = 10/125 = 0.08）。
- 同时报告 t2m 相似度、同类 R@3、中位排名，以及几何指标（MPJPE、终点误差、静止率）。
- 两个系统做比较时，在同一组样本上逐条配对，按来源做 cluster bootstrap 求 95% CI，再配 Wilcoxon 检验。

### 3.9 只在训练期出现：OPD 怎样改这条样本（`opd.py`）

1. 学生对这段视频以温度 1 **自己采样 8 个回答**。
2. 教师给这 8 个回答的每个位置打分，给出完整词表上的概率分布。
3. 计算学生分布和教师分布之间的反向 KL，更新学生的 LoRA。

v6 里这条样本的变化【本地】：

| 模型 | 输出 |
|---|---|
| 真值 | 转身（向右 65°）、拉起同伴、向右跑，3.5 s |
| SFT 学生 | run out of the door；forward / none / 2.5 |
| 8B 教师 | run away；back / around / 2.5 |
| OPD v6 学生 | quickly turn around and run back；back / around / 2.5 |

OPD 之后，学生采纳了教师"转身往回跑"的判断。这和真值 exec 里的 "turns around" 更接近，但方向仍然不对。整个 VAL 上，学生与教师计划完全一致的条目从 60 升到 77；**学生在向教师靠拢，但教师自己也只是略好于学生**，所以总体没有提升（§5.6）。

## 4. 各模块详解

每个模块按同一个顺序讲：**它做什么 → 为什么这样设计 → 我们的具体做法 → 实测结果 → 相关论文**。

### 4.1 任务和数据

**它做什么**：提供"反应前视频 → 反应"的配对样本。

**设计要点**：

- **按来源划分**：同一个源视频切出的片段长得很像。如果它们分散在训练集和验证集里，模型可能只是"认出了视频"，而不是学会了预测。所以用来源 ID、规范化标题和 BV 号做并查集，同一来源的所有片段只进同一组。TEST（182 条）从头到尾封存，从未读取。
- **镜像增广**：视频水平翻转，动作取 x → −x 并交换左右关节，文字里的 left / right 互换。训练集因此从 840 条扩到 1652 条；VAL 不做镜像。有 28 条因为 left / right 不一定是方位词，没有做镜像。
- **规模**：TRAIN 1652（其中真实 840 条）/ VAL 125 / 封存 50 / TEST 182（未发布）。

**实测**【本地】：
- 镜像增广对 SFT 和 OPD 都没有显著作用（v1197aug）。
- 数据从 v860 扩到 v1197 后，在 79 条没有改动的旧 VAL 上，t2m −0.019，CI 跨 0，看不出数据量带来的变化。

**相关工作**：
- 第一人称视频预测：Ego4D 的 Forecasting 基准【文献，2110.07058】、EPIC-KITCHENS-100 的动作预测【文献，2006.13256】。它们预测的是"下一个动作的类别"，我们要的是"全身动作本身"。
- 生成反应动作：双人交互生成 InterGen【文献，2304.05684】，以对方的动作作为条件；我们的条件是第一人称视频。
- 事件级的长短处理：VPP2【文献，2610.10270，读过 HTML 版 §3.1、§4】。

### 4.2 VLM 主干：Qwen3-VL-4B-Instruct

**它做什么**：同时读视频和文字，一个 token 一个 token 地写出答案。

**结构**【本地，config】：

| 部分 | 内容 |
|---|---|
| 视觉编码器 | ViT，24 层，宽 1024；patch 16，时间 patch 2；2×2 合并后投影到 2560 维 |
| DeepStack | 视觉第 5 / 11 / 17 层的特征注入语言模型的前几层 |
| 语言模型 | 36 层，宽 2560，32 个注意力头（8 个 KV 头），FFN 9728，词表 151,936 |
| 输入词嵌入与输出层 | **共享权重**（tied embeddings）。这一点对"最后一层"的讨论很重要，见 §4.10 |

**为什么选 4B**：
- 单卡约 10 GB 就能做 LoRA 训练；
- 实测与 7B 持平；
- 与 8B 共用完全相同的分词器（逐字节相同），所以 8B 教师和 4B 学生可以在整个词表上精确计算 KL（v6 用到了这一点）。8B 也是 36 层，宽 4096。

- Qwen2-VL【文献，2409.12191】：动态分辨率和 M-RoPE（把位置编码拆成时间、高、宽三个分量）。
- Qwen2.5-VL【文献，2502.13923】：把位置编码和绝对时间对齐。

### 4.3 LoRA

**它做什么**：用很少的参数微调大模型。原始权重 W 不动，在旁边加两个"瘦"矩阵：

  W' = W + (α / r) · B · A，  A ∈ ℝ^{r×d_in}，B ∈ ℝ^{d_out×r}，B 初始化为 0

初始化时 W' = W，所以训练从原模型出发。

**我们的做法**【本地，`vt_io.load_model`】：
- r = 16，α = 32，dropout 0.05；
- 加在语言模型 36 层 × 7 个线性层上（q / k / v / o / gate / up / down，共 252 个模块）；
- 共 33,030,144 个参数，不到 1%；视觉编码器冻结。

**为什么在这里近乎必选**：
- 完全不微调：零样本时格式合格率只有 49%【本地】，三行都写不全。
- 全参数微调：光优化器状态就要约 70 GB，而且只有 1.6k 条数据，很容易把语言能力训坏。
- LoRA 可以随时卸下，拿回原版基座。接口 A 正是靠这一点：同一份权重既能当"写答案的学生"，也能当"读文字的冻结编码器"。
- 一个基座可以分别挂学生和教师两份 LoRA。

**相关论文**：
- LoRA【文献，2106.09685】；
- QLoRA【文献，2305.14314】：再加 4-bit 量化，进一步省显存，我们没用；
- "LoRA Learns Less and Forgets Less"【文献，2405.09673】：LoRA 学得少，但遗忘也少。这正好对应我们"保护语言能力"的考虑。

### 4.4 视觉→文本 SFT

**它做什么**：教 VLM 看完视频后写出三行答案。

**teacher forcing 与"暴露偏差"**：训练时，每个位置之前的内容都是**正确答案**；推理时却是**模型自己写的**。一旦前面写错一个词，后面就处在训练时从未见过的状态里。这个训练和推理之间的差异叫暴露偏差。OPD 让学生在自己写出来的句子上学习，就是为了缓解它（§5.2）。

**实测**【本地】：
- VAL NLL：epoch1 0.700，epoch2 0.790（过拟合）。
- 格式合格率 100%。
- 计划准确率约 0.64，只比"永远猜训练集多数类"（0.54）略高。**模型"写得像"，但"决定做什么"仍然很难。**
- 用 Kimodo-TPH 执行时 R@10 约 0.24。路线 6 测过：把 exec 换成人工写的 gt3p（oracle），R@10 可以到 0.44。

**相关论文**：
- 暴露偏差和 scheduled sampling【文献，1506.03099】；
- DAgger【文献，1011.0686】：在学生自己访问到的状态上收集教师标签，是 on-policy 模仿学习的理论基础；
- Chain-of-Thought【文献，2201.11903】：先写中间步骤，再给答案。

### 4.5 动作的表示与"重定向"

**问题**：我们的动捕是 PICO 格式（24 关节，约 80 帧/秒，带时间戳），而大规模的文字–动作数据和评测器都是 HumanML3D 格式。两者必须统一。

**我们的做法**：把 PICO **转成** HumanML3D 格式，而不是反过来把 HumanML3D 转成 PICO（`third_party/umrm_eval/.../pico_to_humanml.py`）：
1. 取 22 个身体关节（去掉手）；
2. 规范化：第一帧骨盆移到原点，朝向固定，脚踩地面；
3. 重采样到 20 帧/秒；
4. 计算 263 维特征：
   - 根节点的转速、水平速度、高度（4 维）；
   - 21 个关节相对根的位置（63 维）；
   - 关节旋转（126 维，6D 表示）；
   - 22 个关节的速度（66 维）；
   - 双脚着地标志（4 维）。

往返误差 3.6e-5 m，骨长比 0.998【本地】。这个格式没有手指，论文里只能称为"HumanML22 口径"。

**为什么是这个方向**：
- HumanML3D 约有 3 万段动作、7 万条描述，预训练权重和评测器（TMR）都基于它；
- 我们的数据转过去几乎无损；
- 反过来转，就要重新训练所有东西。

**"完整事件"**：原数据把动作截在 4.4 秒（88 帧），约 20% 的长反应被砍掉一截。`humanml263_full.npz` 保留整段反应，最长 9.8 秒（196 帧），是从 VPP2 的事件级做法借鉴来的。

**相关论文**：
- HumanML3D：Guo et al., "Generating Diverse and Natural 3D Human Motions from Text", CVPR 2022【文献】，提出了 263 维表示和 R-precision 评测；
- KIT-ML【文献，1607.03827】：更早、更小的文字–动作数据集；
- SMPL（Loper et al. 2015）【文献】：参数化人体模型；
- AMASS【文献，1904.03278】：把多个动捕库统一到 SMPL；
- Motion-X【文献，2307.00818】：带文字的全身动作数据。

### 4.6 为什么用 HumanML3D 预训练，而没用 ego 数据集

动作头要学的是"**文字 → 动作**"，预训练数据就必须是"动作 + 逐段描述"的配对。HumanML3D 正好是这样。第一人称数据集更适合另外两类用途：
- "视频 → 动作"的感知任务，例如 EgoBody【文献，2112.07642】、Ego-Exo4D【文献，2311.18259】；
- 带叙述的日常活动，例如 Nymeria【文献，2406.09905，需核实】。

它们的文字描述大多不是"A person ..."这种逐动作描述，不能直接拿来预训练文本→动作。**这部分我们没有做实验**：可以作为 VLM 一侧的预训练候选（让 VLM 学会从第一人称画面推断身体动作），或者用来扩充动作先验。

### 4.7 RVQ 动作分词器

**它做什么**：把连续的动作压成离散的"动作词"。

**原理**：
1. 编码器把每 4 帧压成一个向量；
2. 在 512 个码字组成的码本里找最近的一个，记下编号，这是第 1 层；
3. 剩下的误差（残差）再用第二本码本逼近，这是第 2 层；
4. 一直做到第 6 层。第 1 层记大轮廓，后面几层补细节；
5. 解码器把 6 层编号还原成 263 维特征。

**为什么用离散表示**：
- 解码器在真实动作上训练，输出天然像"合法的人体动作"，骨头不会伸缩。
- "512 选 1"是分类问题，每个位置都有完整的概率分布。之后可以在动作头上做采样、计算 KL 或者打分。
- **本地负结果**：路线早期试过"冻结 Qwen2.5-VL-3B + flow 头直接回归 88 帧 × 24 关节坐标"。测试误差 0.964 m，比直接输出训练集平均动作（0.914 m）还差；骨长的变异系数 0.19，真人只有 0.014【本地】。

**我们用的**：HERO ViMo 的 RVQ（6 层 × 512，时间下采样 4 倍）在 v860 TRAIN 上微调过的版本（`vq_v860`），训练动作头时保持冻结。

**相关论文**：
- VQ-VAE【文献，1711.00937】；
- 残差向量量化 RVQ，出自音频编解码器 SoundStream【文献，2107.03312】；
- T2M-GPT【文献，2301.06052】：VQ + 自回归 GPT 做文本→动作；
- TM2T【文献，2207.01696】；
- MotionGPT【文献，2306.14795】：把动作 token 当作 LLM 的一种"语言"；
- MoMask【文献，2312.00063】：RVQ + 掩码 Transformer + 残差 Transformer，是我们动作头的直接原型。

### 4.8 掩码 Transformer + 残差 Transformer

**掩码 Transformer（生成第 1 层）**：
- 训练时，随机遮住一部分 token，让它根据条件和没遮住的部分去猜被遮住的；
- 生成时，先全部遮住，每一步保留最有把握的一批，其余重新遮住再猜，共 18 步。
- 和从左到右逐个生成相比，它能并行生成，前后文也可以互相参考。

**残差 Transformer（生成第 2–6 层）**：给定前面几层，预测下一层的编号。

**条件怎么进入**（沿用 HERO 的做法）：
1. 全局向量先对 16 个记忆向量做一次注意力，得到汇总后的条件；
2. 这个条件作为**一个额外的 token 放在动作序列的最前面**；
3. 动作序列的每个位置再通过交叉注意力读取 16 个记忆向量。

残差 Transformer 还会在序列前面再放一个"当前要预测第几层"的 token。

**训练**【本地】：
- 预训练：HumanML3D，6 万步，批大小 64，学习率 2e-4，选验证交叉熵最低的检查点；
- 微调：PICO，3000 步，学习率 1e-4，每 100 步验证一次，选最低点。实测 200–300 步就开始过拟合。

**相关论文**：
- BERT【文献，1810.04805】：掩码预测；
- MaskGIT【文献，2202.04200】：迭代式掩码生成图像；
- MoMask【文献，2312.00063】；
- 扩散类的另一条路：MDM【文献，2209.14916】、MotionDiffuse【文献，2208.15001】。Kimodo 也属于扩散类。

### 4.9 CFG（无分类器引导）

**原理**：
- 训练时，以 10% 的概率把条件清空，让同一个网络同时学会"有条件"和"无条件"两种预测；
- 生成时取 logit = 无条件 + s × (有条件 − 无条件)。s > 1 时，输出更贴合条件。
- 我们用 s = 4（掩码 Transformer）和 s = 5（残差 Transformer）。

**我们修的一个问题**【本地】：HERO 原版清空条件时只清了全局向量，16 个记忆向量仍然可见。这样所谓的"无条件"分支其实还带着条件，引导会失真。我们改成全局和记忆一起清空，训练时的清空和推理时的空条件完全一致。

**相关论文**：Classifier-Free Guidance【文献，2207.12598】。

### 4.10 条件接口："最后一层的语义"到底怎么取（原设想 ⑥⑦）

这是原设想里最有讨论价值的一环。问题是：**动作头应该看 VLM 的哪一部分？**

**演变过程**：

1. **早期版本（负结果）**：冻结 Qwen2.5-VL-3B，把所有 token（包括几百个视觉 token）在最后一层的隐状态取平均，再交给 flow 头直接回归。失败了（§4.7）。
2. **当时的推断**：4B 是 tied-embedding 模型，最后一层隐状态直接与词嵌入矩阵点乘得到 logits，所以它更接近"下一个词是什么"，而不是"这句话是什么意思"。动作头在 A4（第 9 / 18 / 27 / 36 层混合）上学到的层权重也支持这个推断：L9 0.35、L18 0.35、L27 0.14，最后一层只有 0.16。
3. **干净的对照实验**（`vt_lastlayer_v1197aug`）：在相同条件下比较 4 种接口。

| 臂 | 谁来读 | 读什么 | 用哪层 | R@10 | 说明 |
|---|---|---|---|---|---|
| A4 | 冻结原版 4B | 只读 exec 文字 | 9 / 18 / 27 / 36 混合 | 0.235 | 参照 |
| **A36** | 冻结原版 4B | 只读 exec 文字 | **只用最后一层** | **0.291** | 比 A4 高 +0.056，CI [+0.015, +0.101]，**显著** |
| S36 | SFT 学生（挂 LoRA） | 只读 exec 文字 | 最后一层 | 0.243 | 比 A36 低 −0.048，不显著 |
| V36 | SFT 学生 | **视频 + 提示 + 自己的回答** | 最后一层 | 0.253 | 最接近你的原设想；比 S36 高 +0.011，不显著 |

**结论**：
- **最后一层本身没问题，而且最好**。之前"层权重小 → 最后一层不适合"的推断是错的：层权重反映的是 HumanML3D 预训练的目标，和下游效果不是一回事。
- 但这个优势**只在输入是 VLM 预测的文字时出现**；换成人工写的 gt3p 时，A4 0.443、A36 0.424，没有优势。一种可能是最后一层对带噪声的描述更稳健，也可能只是噪声。这是单次运行，还需要复现。
- **"带视频语境的最后一层"（V36）没有带来额外信息**。这和视觉分支 B 的结论一致（见下）：学生看视频时的内部状态，相对于它写出的文字，没有给动作头提供可学的额外信息。

**为什么"冻结原版"比"学生自己"好**：
- 动作头在 HumanML3D 上预训练时，见到的是"冻结原版读文字"的特征。学生挂上 LoRA 之后特征会漂移，而 V36 预训练时只能用"学生只读文字"的特征，推理时却带了视频语境，有分布偏移。
- 动作头的输入和 VLM 的训练解耦：之后用 OPD 改学生时，只会改变"写出什么字"，不会改变"同一句话被编码成什么"。

**视觉分支 B（零初始化门）**【本地，v1197】：
- 做法：条件 = A + g ⊙ B，g 初始化为 0。B 是冻结学生在"视频 + 指令 + 回答"上的隐状态，取 8 个视频时间组的平均和 exec 行的 token。训练起点与"只有 A"完全一样，只有 B 真的有用，梯度才会把门打开。
- 结果：门几乎没有打开；把 B 换成别的样本的视频，结果也不变差。也就是说，动作头没有用到 B。

**相关论文**：
- 用冻结的大语言模型作文本编码器：Imagen【文献，2205.11487】发现文本编码器越大，生成质量提升越明显；LLM2Vec【文献，2404.05961】说明只有解码器的 LLM 也能当很好的文本编码器。
- 哪一层的表示最好：Layer by Layer【文献，2502.02013，需核实】发现中间层常常优于最后一层；logit lens（nostalgebraist，2020 年博客）观察到最后一层越来越接近"下一个词"；Massive Activations【文献，2402.17762】指出中间层存在极大激活值，用之前要先归一化；tied embeddings【文献，1608.05859】。
- VLA 里怎样从 VLM 取条件：
  - RT-2【文献，2307.15818】、OpenVLA【文献，2406.09246】：直接把动作当文字 token 输出；
  - π0【文献，2410.24164】：VLM 加一个 flow 动作专家；
  - GR00T N1【文献，2503.14734】：取 VLM 的中间层（第 12 层）作为条件；
  - π0.5【文献，2504.16054】、Knowledge Insulation【文献，2505.23705，需核实】：动作损失的梯度不回传 VLM，以保护语言知识。我们的"冻结原版重新读文字"更彻底，两边完全分开训练。
- 把变长序列压成固定个数的槽：Perceiver【文献，2103.03206】、BLIP-2 的 Q-Former【文献，2301.12597】。
- 零初始化的门：ControlNet 的 zero convolution【文献，2302.05543】、Flamingo 的 tanh 门【文献，2204.14198】。
- 可学习的查询 token：MetaQuery【文献，2504.06256，需核实】。

### 4.11 预训练 → 微调，以及"完整事件"

- 先在 HumanML3D 上预训练，让动作头学会通用的"指令 → 动作"；再在 PICO 上微调，学会"反应"这类动作的分布。
- 微调目标用**完整事件**（不截断）。生成时的长度仍由 plan 的 duration 决定。
- 实测【本地，v860，探索性】：用完整事件微调后，在 SFT 预测的文字上 R@10 +0.062，CI [+0.008, +0.122]；但在人工 gt3p 输入上没有差异。之后各版本都默认使用完整事件。

### 4.12 对照执行器：Kimodo 与计划编译器

- **Kimodo**【本地工具】：NVIDIA 的文本→动作扩散模型，在我们的实验里保持冻结。
- **两个臂**：
  - T 臂只给文字和时长；
  - TPH 臂再加上"计划编译器"从 plan 换算出的粗略根轨迹和终点朝向（`harness_v1/plan.py` 中的 `coarse_root_path`，统计量只用 TRAIN 计算）。
- **作用**：把"VLM 写得更好"和"自有动作头更好"分开看，形成 {SFT, OPD} × {Kimodo, 自有头} 的 2×2 设计。
- 之前路线 6 试过在 PICO 上微调 Kimodo（Kimodo-FT），数据加多后没有稳定收益【本地】。

### 4.13 评测与统计

**语义指标（主）**：
- TMR【文献，2305.00976】把动作和文字映射到同一空间；
- R@10、t2m 相似度、同类 R@3、中位排名。R-precision 一类的检索指标来自 HumanML3D 原论文。

**几何指标（辅）**：MPJPE、根相对误差、终点误差、静止率。
**为什么 MPJPE 不能当主指标**：合理的反应不止一种。一个"什么都平均一下"的动作 MPJPE 很低，但检索准确率和随机差不多。

**统计方法**：
- 按来源做 cluster bootstrap 求 95% CI（同一来源的片段不独立）【文献：Field & Welsh 2007，Bootstrapping clustered data】；
- 配 Wilcoxon 符号秩检验；
- **事先登记**：每轮训练之前，把主比较、门和容忍线写进 `docs/prereg/`，结果出来后由 `decide_*.py` 机械判定，避免事后挑选。参考：Nosek et al. 2018，"The preregistration revolution"，PNAS【文献】。

**已知偏差**：TMR 和自有动作头都基于 HumanML3D，所以自有头在 TMR 指标上会占"同源"的便宜。要用人评或独立的评价器来校正，这一项还没做。

## 5. OPD 专章：在线自蒸馏与反向 KL（原设想 ⑧）

### 5.1 先从普通蒸馏说起

**知识蒸馏**：让一个学生模型去模仿教师模型的输出分布，而不只是模仿唯一的正确答案。教师给出的"软标签"（比如"向前 0.6、向右 0.3、向后 0.1"）比硬标签包含更多信息【文献：Hinton et al., 1503.02531】。

用在语言模型上，最直接的做法是**离线（off-policy）蒸馏**：让教师写一批答案，学生在这些答案上做 SFT【文献：sequence-level KD，Kim & Rush，1606.07947】。问题在于，学生学的始终是"教师写的句子"，推理时却要接着"自己写的句子"往下写，暴露偏差还在。

### 5.2 On-policy：让学生在自己写的句子上被纠正

OPD（On-Policy Distillation）每一步做的事（`pipeline/opd.py`）：

1. **学生自己写**：学生只看视频，以温度 1 采样 K = 8 个回答。
2. **两边都打分**：把同一批回答分别交给学生（不带 z）和教师（v1–v5 带 z；v6 是 8B 模型），在每个位置各自给出完整词表（151,936 个 token）上的概率分布。
3. **逐位置计算散度**：在每个位置算 KL，只在指定范围内求平均：
   - `re`：只算 reaction 和 exec 两行；
   - `all`：所有回答 token，包括 plan 行和结束符。
4. **只更新学生的 LoRA**，教师冻结。每 4 条样本更新一次，学习率 5e-5。
5. **同步采样副本**：把学生的最新权重复制给负责采样的副本，下一步就用新学生去写。

这和模仿学习里的 DAgger【文献，1011.0686】是同一个思想：**在学生自己会走到的状态上，请教师给出正确的动作分布。** 和强化学习相比，它的信号是逐 token 的、很稠密，不需要奖励模型。训练期间也不调用动作生成器（路线 6 的 DPO 光生成就用了 13,956 次 Kimodo，约 10.5 GPU·h）。

### 5.3 前向 KL 和反向 KL 的区别

某个位置上，学生分布记为 S，教师分布记为 T：

- **前向 KL**：KL(T‖S) = Σ_v T(v)·log[T(v)/S(v)]。教师给了概率的地方，学生都必须给概率，否则惩罚很大。效果是"**覆盖所有可能**"（mass-covering）。SFT 本质上就是对数据分布做前向 KL。
- **反向 KL**：KL(S‖T) = Σ_v S(v)·log[S(v)/T(v)]。学生在教师认为不可能的地方放概率，惩罚很大；但学生可以放弃教师的某些选项。效果是"**挑一个最稳妥的峰**"（mode-seeking）。

我们的代码（逐位置，完整词表）：

```python
lps, lpt = log_softmax(student_logits), log_softmax(teacher_logits)
rev = (lps.exp() * (lps - lpt)).sum(-1)   # KL(S‖T)，反向
fwd = (lpt.exp() * (lpt - lps)).sum(-1)   # KL(T‖S)，前向
loss = ((1 - λ) * rev + λ * fwd)[mask].mean()   # λ = 0 即纯反向 KL
```

为什么主流 OPD 用反向 KL：学生在自己的样本上学习，反向 KL 正好等价于一个强化学习目标，其中每个 token 的"奖励"是 log T − log S。如果学生能力有限、无法覆盖教师的所有模式，就集中学好一个峰，而不是"什么都会一点但都不像"【文献：MiniLLM 2306.08543；Thinking Machines "On-Policy Distillation" 博客，2025-10-27；KL 方向的直观对比见 Minka 2005, "Divergence measures and message passing"】。

### 5.4 为什么"同尺寸自蒸馏"需要特权信息，或者更强的教师

教师和学生如果**权重相同、输入也相同**，两者的输出完全一样，KL 恒为 0，学不到任何东西。要让教师比学生"知道得更多"，只有两条路：

| 路线 | 教师比学生多什么 | 我们的版本 |
|---|---|---|
| **特权信息**（LUPI：learning using privileged information） | 训练时多看一份 z，测试时谁都看不到 | v1–v5 |
| **能力** | 更大的模型、更多的帧、开思考模式……输入和学生一样 | v6（8B 教师） |

文献里的对应工作【文献，详见 `docs/OPD_LITERATURE.md`】：

- **能力型**：MiniLLM、GKD（2306.13649）、Thinking Machines 博客、Qwen3 技术报告（2505.09388）都是"大模型教小模型、输入相同"。RP-OPSD（2607.24447）是同一模型，教师看原分辨率、学生看 1/4 分辨率。
- **上下文型**：Context Distillation（2209.15189）、SDFT。教师的上下文里多了任务通用的指令或示范。
- **答案/证据型**：OPSD（2601.18734）、HDPO（2603.23871）、Video-OPSD（2608.27065）。教师看到参考答案、真值，或者标注好的证据帧。
- **状态型（机器人）**：Learning by Cheating（1912.12294）、RMA（2107.04034）。教师能看到真实的环境状态。
- **理论**：LUPI（Vapnik & Vashist 2009）；Generalized Distillation（1511.03643）把蒸馏和特权信息统一到同一个框架里。

### 5.5 关键陷阱：z 推不出来时，反向 KL 会塌缩到多数类

这是整章最重要的一点。

**情形**：教师看到 z，就知道"这次往前跑"还是"这次往后跑"；学生只看到视频，**从视频推不出 z**。同一段视频在训练集里对应 70% 的"往前"和 30% 的"往后"。

- 教师 A（z = 向前）：P(前) = 0.95，P(后) = 0.05
- 教师 B（z = 向后）：P(前) = 0.05，P(后) = 0.95

学生要在所有 z 上平均地贴近教师，最优解是什么？

| 目标 | 最优学生 | P(前) |
|---|---|---|
| 前向 KL：E_z KL(T_z‖S) | 教师的**算术平均**：0.7×0.95 + 0.3×0.05 | **0.68**（等于真实比例，保留了"往后"的可能） |
| 反向 KL：E_z KL(S‖T_z) | 教师的**几何平均**：∝ 0.95^0.7 × 0.05^0.3 vs 0.05^0.7 × 0.95^0.3 | **0.765**（向多数类偏） |
| 反向 KL，教师更尖锐（0.99 / 0.01） | 同上 | **0.863**（教师越确定，塌缩越严重） |

推导：反向 KL 的目标 E_z Σ_v S(v)[log S(v) − log T_z(v)] 对 S 求最小值，得 S(v) ∝ exp(E_z log T_z(v))，也就是对数概率的平均，即几何平均。

**直观理解**：反向 KL 害怕"学生在某个教师看来不可能的地方放概率"。教师 A 认为"往后"几乎不可能，教师 B 认为"往前"几乎不可能。学生两头为难，就倒向惩罚它的那个教师更少出现的一边，也就是多数类。

**我们实际看到的**【本地，v860 OPD v1：特权教师 + 纯反向 KL + 计划行也算】：
- 预测方向的分布 TV 从 0.22 升到 0.40；最大方向类的占比从 0.48 升到 0.73。
- 预测"向前"的从 46 条涨到 70 条（共 96 条），真值只有 32 条。
- 计划准确率 +0.048 是靠多猜多数类换来的，语义完全没变。

**文献印证**：
- ADVISOR【文献，2007.12173】：教师依赖学生看不到的信息时，这部分信息在模仿中被"边缘化"，形成**模仿鸿沟**（imitation gap）。
- Cai et al. 2024（Provable POMDP with Privileged Information）【文献】：只有在特权状态能由观测历史确定（deterministic filter condition）时，师生蒸馏才高效。
- 2609.38666【文献，只读摘要】：多教师时，前向 KL 的最优解是算术混合，反向 KL 是归一化的几何聚合。
- 2610.09639【文献，只读摘要】：反向 KL 的 OPD 能传递"技能"，几乎传递不了"知识"；换成前向 KL 能恢复知识的传递。

**对策**：
1. 让 z 尽量只包含"从视频推得出来"的信息；
2. 不在 z 决定的字段（例如 plan）上算 KL；
3. 混入前向 KL；
4. 干脆不给 z，改用更强的教师（v6）。

### 5.7 原设想 ⑧ 的现状与下一步

- "OPD 自蒸馏 + 反向 KL"这套**机制**已经完整实现，也验证了：两卡数据并行、断点续训、K 分块计算、可选 KL 范围、可选前向/反向混合。
- 它**没有带来提升**，根本原因不在 OPD 本身，而在"**教师没有既强、又能被学生学到的优势**"。
- 如果继续，开训前先过一道"教师门"：在执行器上确认教师**显著**强于学生，再做 OPD。候选教师：
  1. 更大的模型（例如 Qwen3-VL-32B）；
  2. 同一模型看更多帧或更高分辨率（RP-OPSD 一类，教师多的信息都在同一段视频里，学生原则上推得出来）；
  3. 打开思考模式的教师【文献：2609.20612 发现，不带参考答案的"思考型教师"蒸馏贡献了大部分提升】。

**已经测过的一种视频型教师：自洽共识（G-T7a，2026-10-17）**【本地】
- 设计：标签是标注者选的"最可能的一种"，所以让学生对同一段视频采样 16 次，用语义 MBR 选出"共识答案"作为教师信号。z 完全由视频算出，反向 KL 不会塌缩。
- 结果：不通过。
  - 学生的 MBR 选出的答案，R@10 0.269 vs greedy 0.291；8B 是 0.259 vs 0.315。
  - 温度 1 的单个样本显著差于 greedy（0.223 vs 0.291）。
- oracle@16（16 个里挑最好的）看起来很高，交叉拟合版 0.604。但随机拿 16 条别的视频的描述也有 0.474，这主要是"候选多了总能蒙中"。自己的样本多出的余量（+0.13）不超过单个样本本身的信息（+0.15），所以**没有证据表明"正确答案已经在分布里，只差选出来"**。
- 一个旁证：OPD 的 rollout 正是这些温度 1 样本，它们的质量明显低于 greedy。
- 另一种视频型教师"32 帧"（G-T7b）也不通过：R@10 与 16 帧完全相同（0.291），VAL NLL 也几乎相同。

**把 reason 当学生的输出，以及 R-chain 特权教师（§8，2026-10-18）**【本地】
- 思路：区分**信息型特权**（视频里没有，如标注者选了哪个反应）和**计算型特权**（视频里有、但难提取，如感知要点和推理链）。只有后者能被蒸馏传递。
- 第一部分，reason 当输出：R-CoT（先写推理再回答）0.272、R-obs（先写观察）0.251、R-MT（推理作为辅助任务）0.275，SFT 是 0.291，都不显著，且方向都为负。
- 第二部分，R-chain（规则抽取"感知 + 推理链"、去掉决定）当特权：教师 0.243，并不更强。计划准确率没有上升，说明抽取没有泄漏。按规则不做 OPD。
- 一致的副作用：带推理的模型预测计划的分布更接近真值（不再一味猜多数类），但准确率和语义检索没有提高。
- 到目前为止，所有"视频型"增强（8B、多次采样共识、32 帧、先推理后回答、给教师人工推理链）都没有让学生在单参考评测下变强。下一步最有价值的是测人类上限，或者改用多参考评测。

**主要问题**：

1. **决策是天花板**：
   - 可部署系统的 R@10 在 0.25–0.29 之间；
   - 把 exec 换成人工描述可以到 0.44；
   - 换动作头、做蒸馏，都不会凭空增加视频里的信息。
2. **OPD 缺一个"既强、又能被学到"的教师**（§5.6）。
3. **A36 是单次运行**，而且优势只出现在 VLM 预测的文字上。
4. **评价器与自有头同源**（都基于 HumanML3D），还没有人评或独立评价器来校正。
5. **数据少**：真实训练样本只有 840 条；镜像增广没有用。

**建议的下一步**（按性价比排序）：

1. 复现 A36（换一个种子），并把它定为默认接口。
2. 如果继续 OPD：先用"教师门"确认教师在执行器上**显著**更强，再开训。候选是 32B、更多帧或更高分辨率、思考模式。
3. 加一组小规模人评，校正评价器偏差。
4. 第一人称数据集（EgoBody / Ego-Exo4D / Nymeria）可以作为 VLM 一侧"从画面推断身体动作"的预训练候选。

## 7. 术语表

| 术语 | 解释 |
|---|---|
| VLM | 视觉语言模型，能同时读图像/视频和文字并写文字 |
| token | 模型处理的最小单位。文字被切成子词；视频被切成小块后编码 |
| 隐状态（hidden state） | 每个 token 在模型某一层的向量表示，这里是 2560 维 |
| 最后一层 / 第 36 层 | 语言模型最上面一层（已过最终归一化），与输出词嵌入相连 |
| tied embeddings | 输入词嵌入和输出层共用同一个矩阵 |
| LoRA | 在原权重旁加低秩矩阵的轻量微调方法，可以随时卸下 |
| SFT | 监督微调：用标准答案训练 |
| teacher forcing | 训练时，前文始终是正确答案 |
| 暴露偏差 | 训练时看正确前文、推理时看自己的前文，两者不一致造成的误差 |
| NLL | 负对数似然，即正确 token 概率的负对数，越低越好 |
| greedy / 温度 | greedy 每步取概率最高的 token；温度 1 按原分布采样 |
| gt3p | 人工反应改写成第三人称的动作描述，即 exec 的标准答案 |
| plan | 从动捕自动提取的 5 个离散字段：移动方式、方向、转身、姿态、时长 |
| HumanML3D / 263 维 | 最常用的文字–动作数据集，以及它的动作特征格式 |
| 重定向 | 把一种骨架或格式的动作转换到另一种 |
| RVQ | 残差向量量化：多本码本逐层逼近，把动作变成离散编号 |
| 掩码 Transformer | 遮住一部分 token 再预测；生成时迭代揭开 |
| CFG | 无分类器引导：放大"有条件"和"无条件"预测之间的差异 |
| 接口 A / B | A：冻结原版读 exec 文字；B：学生看视频时的内部状态，经零初始化门加入 |
| A4 / A36 / S36 / V36 | 最后一层实验的 4 个臂（§4.10） |
| Kimodo / T 臂 / TPH 臂 | 冻结的对照生成器；T 只给文字和时长，TPH 再加计划编译出的根路径和朝向 |
| OPD | 在线蒸馏：学生自己采样，教师逐 token 打分 |
| 前向 / 反向 KL | KL(T‖S) 覆盖所有可能；KL(S‖T) 挑一个峰 |
| 特权信息 z | 只在训练时给教师看的信息 |
| 模仿鸿沟 | 教师依赖学生看不到的信息时，模仿必然存在的差距 |
| 塌缩 | 学生的输出向多数类集中，多样性下降 |
| TV 距离 | 两个分布差异的度量（0 到 1）。这里比较预测的 plan 字段分布和真值分布 |
| R@10 | 生成的动作在 125 条描述中把自己那条排进前 10 的比例，随机为 0.08 |
| t2m 相似度 | TMR 空间里，动作和自己那条描述的余弦相似度 |
| MPJPE | 平均关节位置误差（米） |
| cluster bootstrap | 按来源整组重抽样求置信区间 |
| 事先登记 / 门 | 训练前写好比较方法和判定线，事后由脚本机械判定 |
| DDP | 多卡数据并行；我们用两卡 gloo 同步 LoRA 的梯度 |
