# 路线接管记录：4B V→T、A36 T→M 与 OPD

记录时间：2026-10-19 10:59 北京时间。范围：读文档、核对实现和已有实验产物；未启动新训练、迁移数据或修改现有实验。

## 1. 总体设计与当前实现

用户的总体设想是：Qwen3-VL-4B 学会从反应前视频预测反应；通过大规模动作数据预训练动作头；在语义隐状态处连接两段；再用教师指导同尺寸 4B 学生，在学生自己的采样上做反向 KL 蒸馏。

**用户在 2026-10-19 明确补充的核心假设**：此前 OPD 效果不佳，可能是学生本身缺少第一人称场景理解与因果推理能力，因而难以吸收教师特权 reason 所产生的指导。ego 因果预训练用于补足学生的能力基础，再检验特权 reason 的蒸馏是否变得有效。它的价值不能仅由“预训练后 SFT 的动作分数是否直接提高”来判定。此解释是研究假设，尚未被现有实验直接验证。

**用户随后确认的双重目标**：通过 ego 数据增强模型从视频情境推断反应文本的能力，既希望直接改善反应决策并传递到后续动作生成，也希望强化 OPD，让学生更好吸收带 mental reasoning 的教师。直接迁移收益与蒸馏增益分别验证，不能将目标缩减为只提高外部探针或只提高可蒸馏性。能力注入、经过任务 SFT 的保留、最终动作收益以及额外 OPD 收益是需要逐段检查的链条；这些预期仍是待验证假设。

当前已有的可运行链路：

```text
反应前视频
  → Qwen3-VL-4B + 可训练 LoRA
  → <reaction> 第一人称反应
    <exec> 第三人称身体动作描述
    <plan> 移动方式、方向、转身、姿态、时长
  → 冻结原版 4B 纯文本重编码 exec，取第 36 层的 caption token 隐状态
  → 可训练适配器（2560→512，16 个注意力槽 + 全局向量）
  → 掩码 Transformer + 残差 Transformer
  → RVQ 动作码 → 解码为 HumanML263 / HumanML22 动作

动作头训练：HumanML3D 文本—动作 → UMRM 文本—PICO 动作微调
VLM 最新训练：ego 视频—因果/下一步文本 → UMRM 三行目标 SFT
后续 OPD：冻结教师 → 学生采样上的文本分布 KL → 更新学生 LoRA
```

这是分阶段训练的 V→T→M 系统。当前实现没有通过动作损失端到端更新 VLM。动作头也没有参加现有 OPD 的 KL 优化。

工作区正式任务为 `(pre-reaction video, current_state) → reaction → 3D motion`。这条实验线的 `common.PROMPT` 和 `sft.DS` 实际只喂视频与统一提示，没有显式 `current_state` 输入，属于 clip-only 变体。不能将它直接表述成已实现完整的 state-conditioned 正式任务。

## 2. 两条预训练线分别解决什么

| 训练部分 | 数据与监督 | 更新的模块 | 作用 |
|---|---|---|---|
| V→T 外部预训练 | Goal-Step、EgoNormia、EgoRe Why | 4B 语言侧 LoRA | 补足 ego 理解能力，检验是否使学生更能吸收后续特权 reason 蒸馏 |
| V→T 任务 SFT | UMRM 视频→reaction/exec/plan | 同一 LoRA 继续训练 | 学会反应任务和动作生成接口 |
| T→M 预训练 | HumanML3D caption→动作码 | 语义适配器、掩码与残差 Transformer | 建立文本语义到身体动作的映射 |
| T→M 域内微调 | gt3p 文本→PICO 转换后的动作码 | 同上 | 适应反应动捕的动作分布 |
| OPD | 学生 rollout，教师在相同回答前缀上的分布 | 学生 LoRA | 改善学生实际生成时的文本策略 |

动作头复用 HERO/ViMo 组件与初始化；RVQ 在该头训练中固定，不是从零训练全部动作模块。Qwen 文本特征离线缓存，编码器保持冻结。

HumanML3D 主要提供 T→M 能力；普通 ego 视频、理由或问答没有配对全身三维动作，不能直接替代这部分监督。如果后续采用带同步三维姿态的 ego 数据，仍需明确骨架、坐标系、帧率、文本/视频对齐和动作区间后才能训练动作头。

现有“重定向”的实际做法是 **PICO→HumanML263**：统一到 20 Hz、22 关节、规范化根位置与朝向。输出只能按 HumanML22 口径描述，不能称为原生 PICO24 或已有手部精细生成能力。机器人骨架重定向也不在当前已验证链路内。

## 3. “最后一层语义”和 LoRA 的准确含义

“第 36 层”是网络深度，不是只取最后一个 token。当前 A36 对 exec 的多个 caption token 取最后一层隐状态；先归一化、投影，再用注意力压成固定条件。它不直接使用词表 logits，也不把全部视觉/提示 token 简单平均。

| 接口 | 编码器与输入 | VAL R@10 |
|---|---|---:|
| A4 | 冻结原版 4B，exec 纯文本，9/18/27/36 层混合 | 0.235 |
| A36 | 冻结原版 4B，exec 纯文本，第 36 层 | 0.291 |
| S36 | SFT 学生带 LoRA，exec 纯文本，第 36 层 | 0.243 |
| V36 | SFT 学生带 LoRA，视频+提示+回答语境中的 exec，第 36 层 | 0.253 |

来源：[lastlayer 结果](results/lastlayer.md)。A36−A4 为 +0.056，来源级 bootstrap 95% CI [+0.015,+0.101]。V36 最接近“直接用看视频时的最后一层接动作头”，该实验尚未证明它优于 A4 或 S36。不能据此断言视觉隐状态永远无用；预训练与微调的语境偏移、样本量等仍可能影响结果。A36 的优势也尚需跨种子确认。

LoRA 要按位置区分：VLM 学习 V→T 时，当前实际使用语言侧 r16 LoRA，视觉塔冻结；动作头读取语义时，A36 使用不带任务 LoRA 的原版基座。全参微调在方法上可选，现有结果并未证明 LoRA 在理论上必需。“生成侧训练 LoRA、编码侧关闭 LoRA”是当前已验证的工程选择。

这样连接的作用是：后续修改学生，只改变它写出的 exec；相同 exec 的语义编码仍保持一致，减少动作头条件分布随学生权重变化的问题。

## 4. OPD 的训练对象、教师来源与证据

设学生为 S，教师为 T。学生先根据输入 x 采样回答 y，然后两者在同一回答前缀上输出全词表概率：

```text
y ~ S(. | x)
L = E[ mean_t KL(S(. | x, y<t) || T(. | x, z, y<t)) ]
```

这里是逐 token、完整词表的反向 KL；采样路径不反传，教师停止梯度，只更新学生 LoRA。实现还支持与前向 KL 混合，以及只蒸馏 reaction/exec 或蒸馏全部回答。`--lam_fwd 0` 才是纯反向 KL；脚本默认值 0.5 对应混合目标。该逐 token 目标不应不加限定地写成完整序列策略梯度实现。

原始同尺寸路线：4B 教师先用额外信息 z 做 teacher-SFT，然后冻结；4B 学生只看部署可见的信息。z 曾包括动捕计划、mental_reasoning、抽取的观察等。后续也试过无 z 的 8B 教师，属于更大教师到 4B 的蒸馏对照。

**同尺寸不必然要求特权信息。** 严格地说，权重、输入和推理方式都相同且分布相同时，KL 才为零。相同尺寸可以通过更好的训练、不同上下文或计算方式建立教师优势。关键是先验证教师有可迁移的能力优势；“是自己的模型”本身不提供学习信号。

现有结果支持的判断：

- 带强特权的早期纯反向 KL 出现方向多数类偏移；混入前向 KL、排除 plan 后缓解了部分问题。
- v2 在 A+B 头有探索性正结果，但后续复现和换 A36 后未形成稳定主指标收益。
- 8B 无特权教师的纯反向 KL 能使学生向教师靠拢，没有出现同样的塌缩，但教师优势小，最终动作主指标未显著提升。
- 更多帧、共识选择、reason 输出等已有对照，没有提供稳定更强的教师。

因此当前应写“OPD 机制已实现，收益尚未建立”。不可把失败唯一归因于教师、或据此断言 OPD 原理无效。学生的 ego 理解能力不足是用户此次明确提出的待检验解释。现有蒸馏是在语言 token 上进行；动作 token KL、动作头联合蒸馏和端到端优化仍是独立的未完成方案。

必须区分两类 reason 信息：一类能从反应前输入推断，但当前学生尚不会提取或运用；另一类是输入本身未提供的私人意图、未来事实或单一标注者选择。ego 预训练可能改善前一类，不能使后一类凭空变得可观测。此前文档将“学生没学到”笼统解释为“信息不可推断”，证据不足。学生在 OPD 中仍不直接读取 reason，而是通过带 reason 的教师所给出的 token 分布学习。

## 5. 最新 ego 预训练实验及主门结果

`queue_e.sh` 是 V→T 补强实验，已于 2026-10-19 12:01:28 北京时间完成，本身不会继续自动训练 OPD。登记位于原实验 [README §9](prereg/v1197aug.md)。

Goal-Step/EgoNormia 的窗口用于下一步预测；EgoRe Why 采用原片段问答，不能不经逐类审查就宣称全部外部样本都严格满足 UMRM 的 prospective reaction 任务。

阶段 A 的 LoRA 在阶段 B 继续做 UMRM SFT，已选 epoch1；随后固定 A36 头评测。2026-10-19 10:58 主门产物已生成：

### 后续验证设计（原草案；现已登记并启动ER19，见§8）

| 学生初始化 | 不做 OPD | 做同一配方的 reason 教师 OPD |
|---|---|---|
| 原 4B → UMRM SFT | A | B |
| ego 预训练 → UMRM SFT | C | D |

核心比较为 OPD 增益是否因预训练而改变：`(D−C)−(B−A)`，同时报告 D−C 的绝对收益。应保持教师权重、reason 内容/提示、蒸馏数据、KL 方向与 token 范围、训练预算、A36 头和评测协议一致。历史 OPD 使用过不同教师和配方，不能自动拿来构成匹配对照。

若教师也做 ego 预训练，那是另一个变量；应单独区分“学生更容易学”和“教师变得更强”。先核验阶段 B 后是否保留 ego 探针收益、固定教师是否仍有可学优势；OPD 后同时检查独立任务质量、教师一致性、熵与方向分布，不能仅凭训练 KL 下降宣称有效。该设计不受旧登记中 PT-N 的条件约束，但属于新的实验，需要单独明确配置和资源范围。

## 6. 接管时要保留的边界与实现缺口

1. **任务输入**：正式任务含 current_state，这条实验线目前 clip-only；是否扩展输入须另行明确，不能静默混用结果。
2. **数据身份**：正式 benchmark 仍是 636。v860/v1197/v1197aug 是独立实验版本，840 条真实训练扩成 1652 条含镜像训练；VAL 125。它们不自动替代正式 636，642 只作历史溯源。182 条 TEST 封存；50 条 sealed 曾用于已登记的确认实验，不能再称从未使用的新测试集。
3. **完整事件与时长**：动作头训练支持完整事件至 196 帧，但部署端 plan duration 仍为 1.5/2.5/3.5/4.4 秒。支持完整事件训练不等于已支持任意长反应生成。
4. **入口默认值滞后**：`pipeline/train.sh` 默认仍执行早期 A/AB 头和混合 KL OPD。不能直接把它的默认全流程当成“A36 + 最新 ego 预训练 + 纯反向 KL”的统一入口；新实验需要显式对齐配置和产物。
5. **存储**：Ego4D 主视频来自 `/mnt/data/oss/eckes/EgoData/Ego4d/v2_packed/`；8,000 条 EgoRe 视频引用 Shawn 的工作区路径；张量缓存在 `/tmp/vho_ego_cache`。所以大视频主库已在 OSS，但并非全部训练资产和缓存都已迁到 OSS。迁移须与运行中的读取协调，不能直接改路径。
6. **评测**：以上 R@10 是生成动作与标准文本的 TMR 检索指标，不是反应正确率；VAL 规模有限且已进行多轮开发。单次结果不能直接作为泛化结论；TMR 与动作先验都使用 HumanML3D，仍需独立评测或人评补充。
7. **文档时间差**：`ROUTE.md` 的多层混合、未用 ego 数据、下载阻塞等属于早期设计；`GUIDE.md` 正文保留旧版本解释，结果章节更新更多。接管时以对应实验登记、产物和代码为准，不沿用旧文档中的“必须”“最好”作为未经限定的结论。
