# 入门讲解：模块、流程与设计取舍

> 版本说明：本文保留当时的路线与解释。最新结论、ego数据使用和ER19状态见 [实验时间线](EXPERIMENTS.md) 与 [接管记录](TAKEOVER_20261019.md)；“同尺寸必须有特权”“学生已掌握全部可观测信息”等历史判断不作为已证实前提。

目标：看一段第一人称、在"我"做出反应之前截断的视频，预测"我"接下来 1–4 秒会怎样反应，并生成三维人体动作。

## 0. 总图

```
【训练期】
  反应前视频 → 预处理 → Qwen3-VL-4B + 学生LoRA → 三行文字           HumanML3D 预训练 → PICO 微调（动作头）
                                ↑ 逐 token 拉近（OPD）
              Qwen3-VL-4B + 教师LoRA + 特权信息 z（只在训练时可见）
【推理期】
  反应前视频 → 学生 → <reaction> / <exec> / <plan>
                        │          │        └→ 时长 → 动作帧数
                        │          └→ 原版 4B 重读这句话（接口 A）─┐
                        └→ 学生看视频时的内部状态（接口 B，可选）─┼→ 动作头 → 动作 token → 解码 → 22 关节动作
  （对照组：同一段文字交给冻结的 Kimodo 生成动作）
```

## 1. 数据：模型学什么，答案从哪来（`docs/DATA.md`）

每条样本有：反应前视频（输入）；`reaction`（人工写的第一人称"做什么"）；`exec`（gt3p，改写成第三人称的动作描述，即 HumanML3D 的"A person …"风格）；`plan`（从动捕自动提取的移动方式/方向/转身/姿态/时长）；PICO 动捕（动作的真值）；`mental_reasoning`（"为什么这样做"，只给教师看）。

**为什么让 VLM 输出三行**：一行管一层，出了错能定位到是哪一层。reaction 检查决策对不对；exec 把决策翻译成生成器听得懂的指令；plan 补上文字很难说清的量（走多远、往哪走、持续多久）。

**按来源划分**：同一个源视频切出的片段长得很像。如果它们分散在训练集和验证集里，模型可能只是"认出了视频"。所以同一来源的所有片段只进同一组；TEST 从头到尾封存。

**镜像增广**（`data_build/a0_mirror.py`）：视频水平翻转，动作取 x→−x 并交换左右关节，文本里的 left/right 互换。这样把训练集从 840 条扩到 1652 条；VAL 不做镜像。

## 2. 视频怎样变成 token（`prep_video_cache.py`、`vt_io.py`）

均匀抽 16 帧，每帧缩放到不超过 360×640 → 切成 16×16 像素的小块，每 2 帧合成一个时间组（16 帧 → 8 组）→ 视觉编码后，相邻 2×2 个块合成一个 token。一段视频约 1,670 个视频 token。每段视频只预处理一次并缓存。镜像样本在这一步翻转。
transformers 5.3 的兼容修复见 `vt_io.per_frame_grid`（envs/README.md 有说明）。

## 3. Qwen3-VL-4B 主干

视觉编码器（ViT，24 层）→ 合并投影到 2560 维 → 语言模型（36 层，词表约 15 万）。视觉 token 和文字 token 在同一个序列里，模型一个 token 一个 token 地往后写。视觉编码器第 5、11、17 层的特征还会直接注入语言模型的前几层（deepstack）。选 4B 的原因：单卡约 10 GB 就能做 LoRA 训练，实测与 7B 持平，同尺寸师生可以共用一份基座权重。

## 4. LoRA（`vt_io.load_model`）

不改原始权重 W，在旁边加一对很"瘦"的矩阵：W + (α/r)·B·A，秩 r=16。只加在语言模型 36 层 × 7 个线性层上（约 3300 万参数，不到 1%），视觉编码器冻结。它在这里近乎必选：完全冻结时零样本格式都写不对；全参微调光优化器状态就要约 70 GB，而且容易把语言能力训坏。LoRA 还能随时关掉、拿回原版基座，接口 A 正是靠这一点；一个基座也可以同时挂学生和教师两个 LoRA。

## 5. 视觉→文本 SFT（`sft.py`）

用 teacher forcing：把正确的三行答案整句喂进去，在每个位置预测下一个 token，用交叉熵衡量错多少，只在答案部分算损失。学习率 1e-4，最多 3 个 epoch，每 8 条累积一次梯度；每个 epoch 结束后在 VAL 上算每个 token 的平均 NLL，取最低的那个 epoch。训两份：学生（只看视频）和教师（视频 + 特权信息 z），两者要写的答案完全相同。

## 6. 动作的表示（`third_party/.../pico_to_humanml.py`）

PICO 24 关节，约 80 帧/秒 → 规范化（第一帧骨盆移到原点、朝向固定、脚踩地面）→ 重采样到 20 帧/秒 → HumanML3D 的 263 维特征：根的转速/水平速度/高度（4 维）+ 21 个关节相对根的位置（63）+ 关节旋转（126）+ 22 个关节的速度（66）+ 双脚着地（4）。这个格式只有 22 个关节、没有手，所以论文里只能称为 HumanML22 口径。

**为什么把 PICO 转成 HumanML3D，而不是反过来**：HumanML3D 约有 3 万段动作、7 万条描述，预训练权重和评测器都基于这个格式；我们的数据转过去几乎无损。

**完整事件**（借鉴 VPP2）：原数据把动作截在 4.4 秒，约 20% 的长反应被砍掉一截。`humanml263_full.npz` 保留整段反应，最长 9.8 秒。

## 7. 动作头：文本→动作（`head.py`）

- **RVQ 动作分词器**：每 4 帧压成一个向量，在 512 个码字的码本里找最接近的，记下编号；剩下的误差再用第二本码本逼近，一共 6 层（第 1 层记大轮廓，后几层补细节）。解码器保证输出是合法的人体动作，而且"512 选 1"是分类，有概率分布。
- **掩码 Transformer**：生成第 1 层编号。训练时随机遮住一部分让它猜；生成时先全部遮住，每步保留最有把握的一批，其余重新遮住再猜，共 18 步。
- **残差 Transformer**：在第 1 层的基础上依次补齐第 2–6 层编号。
- **CFG**：训练时以 10% 的概率清空条件；生成时取"有条件 + s×（有条件 − 无条件）"。这里修了 HERO 的一个问题：原版清空条件时只清了全局向量，文字的逐 token 记忆仍然可见。
- **动作长度**由 `<plan>` 里的 duration 决定（1.5/2.5/3.5/4.4 秒 → 30/50/70/88 帧）。
- **训练**：先在 HumanML3D 上预训练（`head.py pretrain`，6 万步）；自检 R@3 为 0.855，同一分词器重建的真实动作为 0.860。再在 PICO 上微调（`head.py finetune`），按 VAL 上的交叉熵选点；实测总在 200–300 步就开始过拟合。

## 8. 接口 A 和接口 B：把"意思"交给动作头

- **接口 A**（`textenc.py` + `head.QwenAdapter`）：把 `<exec> A person …` 交给**关掉 LoRA 的原版 4B** 只读文字，取第 9/18/27/36 层的隐状态 → 每层 LayerNorm → softmax 学一组层权重 → 小 MLP 降到 512 维 → 16 个查询槽做注意力池化得到 16 个记忆向量，再加 1 个全局平均向量。实测学到的层权重：L9 0.35、L18 0.35、L27 0.14，最后一层只有 0.16。原因是最后一层与输出词嵌入共享权重，更贴近"下一个词是什么"，而不是"这句话是什么意思"。之所以关掉 LoRA，是为了让条件和 HumanML3D 预训练时一致，并且 OPD 改学生时不会改变动作头看到的输入。
- **接口 B**（`vis_feats.py` + `head.VisAdapter/Cond`）：取冻结学生在"视频 + 指令 + 回答"上的隐状态，包括 8 个视频时间组的平均和 exec 那一行的 token。以**条件 = A + g⊙B（g 初始为 0）**的方式加进来（ControlNet 的思路）：训练起点与只有 A 完全一样，有用时门才会被梯度打开。对照实验：把 B 换成别的样本的视频（`--vis-shift`）。

## 9. 特权教师与 OPD（`opd.py`）

- **为什么需要特权信息**：同尺寸、同输入的教师和学生输出完全一样，KL 恒为 0，什么都学不到。所以教师在训练时能看到额外的 z：运动学信息（时长、位移、转角、走/跑/蹲）+ mental_reasoning（我注意到了什么、为什么这样做）。测试时谁都看不到 z。教师单独训一个 LoRA，在 OPD 里冻结，否则它会学会忽略 z。
- **每一步做什么**：① 学生只看视频，以温度 1 自己采样 K 个回答（on-policy）；② 同一批回答分别交给学生（不带 z）和教师（带 z），在每个位置各自给出完整词表上的概率分布；③ 在每个位置计算 0.5·KL(学生‖教师) + 0.5·KL(教师‖学生)，**只在 reaction 和 exec 两行**上算，只更新学生的 LoRA；④ 把学生的最新权重同步给采样副本。训练期间不调用生成器，也不需要奖励模型。
- **为什么不用纯反向 KL**：z 推不出来的时候，反向 KL 的最优学生是各教师分布的几何平均，会向多数类塌缩。v860 的 OPD v1 就发生了：预测"向前"从 46 条涨到 70 条，真值只有 32 条。去掉计划行的 KL、再混入前向 KL 之后，v2 的方向偏移从 +0.18 降到 +0.04。
- **工程**：两卡数据并行（`run_opd_ddp.sh`，梯度与单卡相同）、K 分块计算、每 25 步存一次断点、必须显式 `student.train()`（否则梯度检查点不生效，一条序列就占 17 GB）。

## 10. 执行器：Kimodo 对照与自有头

Kimodo（NVIDIA，冻结）：T 臂只给文字 + 时长；TPH 臂再加"计划编译器"换算出的根路径和终点朝向。自有头只用时长。两者都报，用 2×2 设计（{SFT, OPD} × {Kimodo, 自有头}）把"VLM 写得更好"和"生成器更好"分开看。

## 11. 评测（`eval_head.py`、`eval_kimodo.py`、`compare.py`）

- **语义（主）**：官方 HumanML3D TMR 把动作和文字映射到同一个空间。R@10 = 生成动作和本组所有标准描述逐一比较，自己那条排进前 10 就算命中（随机 = 10/N）；t2m 相似度；同类 R@3；中位排名。
- **几何（辅）**：MPJPE、根相对误差、终点误差、静止率。MPJPE 不能当主指标：合理的反应不止一种，"什么都平均一下"的动作 MPJPE 很低，但检索准确率等于随机。
- **统计**：按来源做 cluster bootstrap 求 95% CI，再配 Wilcoxon。每轮训练前把门写进 `docs/prereg/`，结果出来后由脚本机械判定。
- **评价器同源**：TMR 和自有头都基于 HumanML3D，自有头在 TMR 指标上会占便宜，要靠人评或独立评价器来校正。
